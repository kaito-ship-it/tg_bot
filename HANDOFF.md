# Передача проекта разработчикам

Эта копия не должна содержать действующие ключи, личные Telegram-сессии,
сохранённый вход в админку или обработанные новости.

## Что передаётся

- исходный код из `app/`, `scripts/`, `tests/`, `userscript/` и `deploy/`;
- зависимости и документация;
- `.env.example` для локальной разработки;
- `.env.production.example` для VPS без личного Telegram-аккаунта.

## Что каждый разработчик создаёт самостоятельно

1. Копирует подходящий шаблон в `.env`.
2. Получает новые секреты через защищённый канал:
   - токен служебного Telegram-бота;
   - ID исходного канала, рабочего чата и редакторов;
   - случайный `TG_WEBHOOK_SECRET`;
   - `NEWS_BOT_API_TOKEN` от backend-разработчика;
   - OpenAI API key, только если нужны AI-обложки/классификация.
3. Не использует старые ключи из локальной разработки или переписки.

## Проверка перед push

```bash
python scripts/check_no_secrets.py
python -m pytest
```

Коммитить запрещено:

- `.env` и любые локальные варианты `.env.*`;
- `*.session`, `*.session-journal`;
- `data/` (там могут быть cookie, статьи, изображения, ID чатов и очереди);
- `.venv/`, кэши, логи и диагностические скриншоты.

## Продакшен-схема

На VPS используйте `TELEGRAM_INGEST_MODE=webhook` и
`PUBLISH_MODE=backend_api`. В этом режиме `TG_API_ID`, `TG_API_HASH`, личный
номер телефона, Telegram session-файл и cookie админки не нужны. Полная
инструкция находится в `deploy/README_VPS.md`.

Перед первым запуском владелец инфраструктуры должен перевыпустить все ранее
использовавшиеся токены и проверить права служебного бота. Старые значения
следует считать скомпрометированными.
